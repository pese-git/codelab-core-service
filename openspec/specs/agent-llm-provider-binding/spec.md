## Requirements
### Requirement: Агент ДОЛЖЕН иметь обязательный LLM провайдер
При создании агента пользователь ДОЛЖЕН указать llm_provider_id, который однозначно определяет, какой LLM провайдер использует этот агент.

#### Scenario: Создание агента с провайдером
- **WHEN** пользователь отправляет POST /my/projects/{project_id}/agents с {name: "Assistant", llm_provider_id: "550e8400-..."}
- **THEN** система валидирует, что провайдер существует и принадлежит пользователю, создает агента с llm_provider_id, возвращает 201 Created

#### Scenario: Попытка создать агента без провайдера
- **WHEN** пользователь отправляет POST /my/projects/{project_id}/agents без поля llm_provider_id
- **THEN** система возвращает 400 Bad Request с сообщением об ошибке: "llm_provider_id is required"

#### Scenario: Попытка создать агента с несуществующим провайдером
- **WHEN** пользователь отправляет POST /my/projects/{project_id}/agents с llm_provider_id: "nonexistent-id"
- **THEN** система возвращает 400 Bad Request с сообщением: "LLM provider not found or not active"

#### Scenario: Попытка создать агента с провайдером другого пользователя
- **WHEN** пользователь A пытается создать агента с llm_provider_id провайдера пользователя B
- **THEN** система возвращает 400 Bad Request (скрывает факт существования провайдера)

### Requirement: Агент использует litellm_model_name провайдера при выполнении
При выполнении промпта агент ДОЛЖЕН использовать litellm_model_name своего привязанного провайдера вместо конфигурации по умолчанию.

#### Scenario: Агент использует модель провайдера
- **WHEN** агент выполняет промпт к LLM
- **THEN** система использует model = provider.litellm_model_name вместо config.model

#### Scenario: Агент передает config провайдера в LLM
- **WHEN** агент выполняет промпт
- **THEN** система передает в LiteLLM дополнительные параметры из provider.config (temperature, top_p и т.д.)

### Requirement: Система валидирует наличие провайдера перед использованием
При выполнении агента система ДОЛЖНА проверить, что привязанный провайдер существует и активен.

#### Scenario: Успешная валидация провайдера
- **WHEN** агент начинает выполнение
- **THEN** система загружает провайдер из БД, проверяет status = "active", позволяет выполнение

#### Scenario: Провайдер инактивен
- **WHEN** агент пытается выполниться и его провайдер имеет status = "inactive"
- **THEN** система возвращает ошибку: "LLM provider is inactive", не выполняет промпт

#### Scenario: Провайдер был удален
- **WHEN** агент пытается выполниться и его провайдер больше не существует
- **THEN** система возвращает ошибку: "LLM provider not found", логирует в audit

### Requirement: Система обновляет статистику использования провайдера
При каждом успешном выполнении агента с провайдером ДОЛЖНЫ быть обновлены usage_count и last_used_at провайдера.

#### Scenario: Обновление usage_count после выполнения
- **WHEN** агент успешно выполняет промпт
- **THEN** система увеличивает provider.usage_count на 1, устанавливает provider.last_used_at = now(), логирует action="use" в audit

#### Scenario: Использование не обновляется при ошибке
- **WHEN** агент пытается выполнить промпт и происходит ошибка (невалидный ключ и т.д.)
- **THEN** система НЕ увеличивает usage_count, логирует ошибку в audit с action="use", success=false

### Requirement: Пользователь может просмотреть провайдер агента
При получении информации об агенте должна быть включена информация о его привязанном провайдере.

#### Scenario: GET агента содержит информацию о провайдере
- **WHEN** пользователь отправляет GET /my/projects/{project_id}/agents/{agent_id}
- **THEN** система возвращает 200 OK с полной информацией агента, включая {llm_provider_id, provider: {id, display_name, provider_type, litellm_model_name, status}}

### Requirement: Пользователь может изменить провайдер агента
Пользователь ДОЛЖЕН иметь возможность изменить, какой провайдер использует агент (при условии, что текущий провайдер не используется другими агентами или можно переключиться).

#### Scenario: Успешное изменение провайдера агента
- **WHEN** пользователь отправляет PATCH /my/projects/{project_id}/agents/{agent_id} с {llm_provider_id: "new-provider-id"}
- **THEN** система валидирует новый провайдер, обновляет связь, логирует в audit, возвращает 200 OK

#### Scenario: Попытка изменить на несуществующий провайдер
- **WHEN** пользователь пытается изменить провайдер на несуществующий
- **THEN** система возвращает 400 Bad Request

### Requirement: Система логирует привязку провайдеров к агентам
При создании/изменении привязки провайдера ДОЛЖНА быть создана запись аудита.

#### Scenario: Логирование создания агента с провайдером
- **WHEN** пользователь создает агента с провайдером
- **THEN** система логирует в llm_provider_audit_log с action="agent_created", success=true, содержащей информацию об агенте и провайдере

#### Scenario: Логирование изменения провайдера агента
- **WHEN** пользователь изменяет провайдер агента
- **THEN** система логирует с action="provider_reassigned", old_values={old_provider_id}, new_values={new_provider_id}
