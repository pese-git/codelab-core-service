## Фаза 1: Основная инфраструктура (✅ Завершена)

### Созданные файлы

#### [`app/services/langfuse_decorators.py`](app/services/langfuse_decorators.py:1) (255 строк)
Предоставляет два декоратора для автоматического трейсинга:

**@trace_llm_call** - Автоматически трейсит вызовы OpenAI LLM
- Захватывает: модель, сообщения, вызовы инструментов, токены, задержку
- Захватывает ВСЕ варианты ответов (не только первый)
- Опциональный параметр `max_output_length` для ограничения вывода
- Возвращает: Полный ответ с метаданными

**@trace_embedding_call** - Трейсит генерацию встраиваний
- Захватывает: модель встраивания, входной текст, размерность
- Возвращает: Полные векторы встраивания

#### [`app/services/quality_metrics.py`](app/services/quality_metrics.py:1) (284 строки)
Асинхронные статические методы для записи метрик качества:
- `record_task_completion()` - успех/неудача задачи
- `record_context_relevance()` - качество поиска RAG
- `record_tool_execution()` - успех/неудача вызова инструмента
- `record_response_quality()` - удовлетворённость ответом
- `record_llm_cost()` - использование токенов и стоимость
- `record_agent_handoff()` - метрики маршрутизации агента

#### [`app/routes/feedback.py`](app/routes/feedback.py) (Создано)
REST API endpoints для сбора обратной связи пользователя:
- `POST /feedback/traces/{trace_id}/rating` - Оценки звёздами
- `POST /feedback/thumbs` - Лайк/дизлайк
- `POST /feedback/scores/{score_name}` - Пользовательские оценки

#### [`doc/LANGFUSE_INTEGRATION_IMPROVEMENTS.md`](doc/LANGFUSE_INTEGRATION_IMPROVEMENTS.md)

## Текущая архитектура

```
Запрос сообщения (POST /chat/{session_id}/message)
    ↓
handle_message() - Создаёт трейс сессии
    ├─ метаданные: user_id, project_id, session_id, execution_mode
    │
    ├─→ Путь прямого выполнения
    │    └─→ ContextualAgent.execute()
    │         └─→ _call_llm_with_trace() [2 вызова на выполнение]
    │              ├─ Начальное рассуждение с контекстом
    │              └─ Финальная генерация ответа
    │
    └─→ Путь оркестрированного выполнения
         └─→ OrchestratorRouter (маршрутизация мультиагента)
              └─→ Выполнение выбранного агента (то же самое, что Direct)
```

### Поток данных

1. **Уровень сессии**: `handle_message()` создаёт трейс с контекстом
2. **Уровень агента**: `ContextualAgent._call_llm_with_trace()` создаёт спаны для каждого вызова LLM
3. **Все спаны** включают: задержку, токены, стоимость, полное содержание ответа
4. **Трейсы сбрасываются** в Langfuse при завершении запроса

## Известные проблемы и исправления

### Проблема 1: AttributeError - 'workspace_id'
**Статус**: ✅ Исправлено  
**Корневая причина**: Ссылка на несуществующий атрибут `self.workspace_id`  
**Решение**: Изменено на `self.user_id` (правильное имя атрибута)  
**Коммит**: 0c90cbd

### Проблема 2: Передача недопустимого параметра
**Статус**: ✅ Исправлено  
**Корневая причина**: Попытка передачи `langfuse_trace` методам, которые его не принимают  
**Решение**: Параметры удалены, трейсы управляются только на уровне сессии  
**Коммит**: 0c90cbd

### Проблема 3: QualityMetricsCollector API
**Статус**: ⚠️ Отложено  
**Корневая причина**: Langfuse SDK не имеет метода `.score()`, использует `.record_score()` на клиенте  
**Текущее состояние**: Вызовы метрик качества удалены из handle_message()  
**Дальше**: Исправить сигнатуры методов при реализации Фазы 5
