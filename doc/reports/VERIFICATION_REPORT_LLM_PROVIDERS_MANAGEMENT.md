### Исправления применены:

**Группа 1: Архитектура**
1. ✅ **design.md (строка 259)** - Обновлена ER диаграмма USER_AGENTS: удалено `"optional"` из поля `llm_provider_id`, теперь оно обязательное (NOT NULL)

**Группа 2: Интеграция с агентами**
2. ✅ **tasks.md:8.8** - Добавлена задача: "Реализовать PATCH для изменения llm_provider_id агента (валидация, логирование с action='provider_reassigned')"
3. ✅ **tasks.md:8.9** - Переименована на тесты интеграции с логированием action values

**Группа 3: Обработка ошибок и resilience**
4. ✅ **tasks.md раздел 9** - Добавлены 3 новые задачи:
   - 9.1: Retry logic с exponential backoff для LiteLLM (макс 3 попытки, стартовая задержка 1s)
   - 9.2: Валидация запрета обновления api_key в update_user_provider()
   - 9.3: Тесты для timeout scenarios (60s timeout) в unit/integration тестах

**Группа 4: Контроль доступа к endpoints**
5. ✅ **tasks.md:7.2-7.10** - Добавлено явное определение доступа:
   - Все `/my/*` endpoints требуют авторизацию (приватные)
   - Только `GET /llm-providers/types` - публичный endpoint без авторизации
   - tasks.md:7.12: Документировать доступ к endpoints
   - tasks.md:7.13: Тесты на 403 Forbidden для неавторизованного доступа

**Группа 5: Унификация audit log action values**
6. ✅ **tasks.md раздел 5** - Унифицированы action values:
   - 5.2: Валидация action values при логировании
   - 5.4: Документировать допустимые значения: `create`, `update`, `delete`, `test`, `use`, `provider_reassigned`

7. ✅ **tasks.md раздел 8** - Явное логирование action values:
   - 8.5: Логирование с `action="use"` при использовании провайдера в агенте
   - 8.8: Логирование с `action="provider_reassigned"` при смене провайдера агента
